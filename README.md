# 회의 후속 정리기

회의 녹음이나 전사본을 넣으면 AI가 **결정사항, 내 할 일(기한), 개발자 확인 요청, 다시 물어볼 것, BM 논의·가설** 초안을 만듭니다. PM이 검토·승인해야 저장되고 할 일 보드에 쌓입니다.

함께 들어 있는 기능:

- **오늘** (첫 화면): 기한 지남·오늘 마감·3일 안 마감·기한 미정 항목을 한눈에 보고 바로 완료 처리
- **정책 Q&A**: 노션 정책 페이지(하위 페이지·인라인 DB까지) 또는 `knowledge/policies/`의 문서만 근거로 답하고, 인용마다 해당 노션 페이지 바로가기를 달며, 인용문이 원문과 같은지 시스템이 다시 확인. 문서에 없으면 "찾을 수 없어요"와 확인할 담당자를 안내
- **문구 검수**: 기획서·공지 문구가 실제 사이트 화면 표기(노션 "UI 문구 용어집" DB와 혼용 포인트)와 맞는지 AI가 검수, 결과를 `output/검수_*.md`로 저장

**데모 (설치 없이 보기)**: https://meeting-followup-six.vercel.app  
연습 모드라 AI 대신 정해진 예시 결과가 나오고, 노션 연동은 꺼져 있습니다. 입력한 기록은 서버가 쉬면 사라집니다.

발표용 업데이트 정리: [발표_업데이트.md](발표_업데이트.md) · 과제 제출 문서: [제출문서.md](제출문서.md)

## 실행 방법

준비물: Node.js 20.6 이상, Claude API 키 (녹음 변환까지 쓰려면 OpenAI 키도)

```bash
npm install
cp .env.example .env      # .env 를 열어 ANTHROPIC_API_KEY 를 넣는다
npm start                 # http://localhost:3000
```

- 회의 정리는 Claude(`claude-opus-5-5`)가 합니다.
- Claude에는 음성 인식이 없어서, 녹음 파일 변환은 `OPENAI_API_KEY`가 있을 때만 켜집니다 (OpenAI Whisper). 없으면 클로바노트 등에서 뽑은 전사본을 붙여넣습니다.

키 없이 화면 흐름만 볼 때는 연습 모드로 켭니다. AI를 부르지 않고 `samples/mock-analysis.json`을 결과로 씁니다. 화면 위쪽에 "연습 모드" 표시가 나옵니다.

```bash
npm run mock
```

## 노션 연동 (선택)

`NOTION_TOKEN`이 있으면 다음이 켜집니다. 없으면 로컬 파일만 씁니다.

| 앱에서 하는 일 | 노션에서 일어나는 일 |
| --- | --- |
| 회의 승인 | 회의록 LIST에 페이지 생성 (이름·날짜·참석자·버전 + 결정·할 일·확인 요청·BM 본문) |
| 회의 승인 | 내 할 일마다 주간 캘린더에 '대기' 카드 생성, 회의록 페이지와 연결 |
| 할 일 완료 / 되돌리기 | 카드 상태를 '완료' / '대기'로 변경 |
| 새 버전 승인 | 이전 회의록은 '대체됨', 이전 버전의 미완료 카드는 휴지통으로 |
| 정책 Q&A | 운영정책 페이지의 하위 페이지·인라인 DB 행까지 읽어 근거로 씀. 서버 시작 때 미리 읽고 10분마다 뒤에서 갱신, 화면의 '노션에서 다시 불러오기'로 즉시 갱신 |
| 할 일 답변 기록 | 회의록 페이지의 '후속 진행 기록'에 한 줄 추가 |
| 팀 설정 / 회의 정리 | '팀·구성원' DB의 팀 선택지 = 앱의 팀 목록, 구성원 이름·별칭 = AI의 팀 분류 명단. 앱에서 팀·구성원을 추가·수정하면 노션에 바로 반영 (1분 캐시) |

설정:
1. [notion.so/profile/integrations](https://www.notion.so/profile/integrations) → 새 통합(내부) → 권한: 콘텐츠 읽기·업데이트·입력 → 시크릿 복사
2. 연동할 노션 페이지 → 오른쪽 위 `…` → 연결 → 방금 만든 통합 추가 (하위 DB·페이지에 함께 적용)
3. `.env`의 `NOTION_TOKEN=` 뒤에 시크릿을, 각 `NOTION_*_ID`에 DB·페이지 링크의 32자리 ID를 넣고 서버를 다시 켭니다. 비워 둔 항목의 기능만 꺼지고 나머지는 로컬 파일로 동작합니다.

노션 전송이 실패해도 승인과 로컬 저장은 그대로 남고, 회의 이력의 `노션으로 보내기`로 다시 보낼 수 있습니다.

## 시연 순서 (예제 입력)

1. **새 회의 정리** → 클로바노트 음성기록 `.txt` 파일을 끌어다 놓기 (제목·날짜·참석자·전사본 자동 입력). 예시는 `예시 회의 불러오기`, 녹음은 `녹음 파일 올리기` (OpenAI 키 필요)
2. `AI로 정리하기` → 검토 화면에서 근거 문장과 대조해 고치기
   - 주황색 기한 칸 = AI가 날짜를 확정하지 못한 곳 → 직접 입력
   - BM 가설은 기본으로 꺼져 있음 → 채택할 것만 체크
3. `검토 완료 · 승인` → `output/<회의ID>_v1.md` 저장, 할 일 보드로 이동
4. **할 일 보드**에서 D-day 확인, 상태를 `완료`·`답변 받음`으로 변경
5. **회의 이력** → `재분석 (새 버전 만들기)` → v2 승인 → v1과 이전 기록이 그대로 남는지 확인
6. **오늘** → 기한별로 모인 항목 확인, `완료`·`답변 받음` 처리
7. **정책 Q&A** → 예시 질문 클릭 (정책에 있는 질문, 없는 질문(좌석 배치) 각각)
8. **문구 검수** → `예시 문구 불러오기` → `검수하기` → 결과 파일 열기

정책 문서와 용어집은 파일만 바꾸면 됩니다. 노션·지라에서 Markdown으로 내보낸 정책을 `knowledge/policies/`에 넣고, 용어집은 같은 열 구성의 CSV로 바꿉니다. 지금 들어 있는 정책·용어집은 모두 가상 자료입니다.

## 저장되는 곳

| 경로 | 내용 | 규칙 |
| --- | --- | --- |
| `data/meetings.json` | 회의, 전사본, 버전별 AI 초안·승인본 | AI 초안은 고치지 않음. 새 버전이 승인되면 이전 버전은 `대체됨` |
| `data/tasks.json` | 할 일·확인 요청·질문 (누적) | 완료한 항목은 새 버전이 나와도 보존 |
| `data/history.jsonl` | 등록·초안·승인·상태 변경 기록 | 한 줄씩 쌓기만 하고 지우지 않음 |
| `output/<회의ID>_v<n>.md` | 승인된 정리본 | 노션·슬랙에 붙여넣기용 |
| `data/policy_qa.jsonl` | 정책 질문·답·인용·원문 일치 여부 | 쌓기만 함 |
| `output/검수_<시각>.md` | 문구 검수 결과 | 같은 시각이어도 덮어쓰지 않음 |

녹음 원본은 텍스트로 바꾼 뒤 서버에서 바로 지웁니다.

## 구조

```
server.js          API (전사, 정리, 재분석, 승인, 할 일 상태)
lib/ai.js          Claude 호출 (구조화 출력으로 정리), 선택: OpenAI Whisper 전사
lib/store.js       JSON 저장 + 이력 로그
lib/markdown.js    승인본·검수 결과 → Markdown
lib/knowledge.js   정책 문서·용어집 읽기, 용어 규칙 검사
knowledge/         정책 문서(가상), 용어집(가상)
public/            화면 (HTML·CSS·JS)
samples/           가상 회의 전사본·녹음, 연습 모드 결과
```

## 남은 문제

- 화자 구분이 없습니다. 전사본에 말한 사람 이름이 없으면 대상·담당자가 틀릴 수 있어 검토 화면에서 꼭 확인해야 합니다.
- AI 결과는 실행할 때마다 조금씩 다릅니다 (항목 수·문장). 그래서 PM 검토·승인 단계를 둡니다.
- 로그인이 없어 한 사람(PM)이 로컬에서 쓰는 것을 전제로 합니다.
- 노션은 앱 → 노션 방향만 씁니다. 노션에서 카드를 완료해도 앱에는 반영되지 않습니다. Jira 연동은 없습니다.
- 노션 정책을 하위 DB까지 읽으면 요청 한도 때문에 1분 넘게 걸립니다 (서버 시작 때 미리 읽어 둠).
- 정책 문서가 많아지면(수십 개 이상) 전부를 한 번에 AI에 보내는 지금 방식 대신 검색(RAG)이 필요합니다.
- 녹음 변환은 OpenAI 키가 따로 필요하고, 25MB가 넘는 녹음은 나눠서 올려야 합니다.
